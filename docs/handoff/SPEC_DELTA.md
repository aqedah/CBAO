# 기존 v1.0 명세에 대한 추가·변경 사항

본 문서는 **시각 표현과 화면 구조에 한하여** `reference/AI_OFFICE_V1_SPEC.original.md`보다 우선한다. 업무 규칙, 승인, 권한, Runner, 재연결, 비용, 보존 정책은 변경하지 않는다. 원본 문서는 실제로 수정하지 않았으며 참조용 복사본을 보존했다.

## D01. 사무실 표현

기존 §0: `실제 업무 카드가 놓인 팀원 자리. 3D·아바타 애니메이션은 제외`.

변경: `메인 대시보드 + 같은 업무 데이터를 보여주는 따뜻한 픽셀 사무실. 고정 등각 시점의 2.5D 장면과 상태에 근거한 아바타 동작을 추가한다. 자유 회전 실제 3D 모델은 후속 선택 사항이다.`

## D02. 화면 경로

기존 `#/office`와 S10은 메인 대시보드로 보존한다. S11 `#/office/room`을 추가한다. 상시 메뉴를 늘리지 않고 사무실의 두 가지 보기로 전환한다. 최초 진입은 대시보드다. 픽셀 사무실의 직접 링크는 허용한다.

## D03. 렌더러

기존 §8의 '3D 엔진을 처음부터 추가하지 않는다'는 기본 취지는 유지한다. 시각화 전용 **PixiJS 8.x 2D 렌더러**의 지연 로딩을 허용한다. Three.js, 게임 물리엔진, 다중 에이전트 오케스트레이터를 이번 화면 추가의 필수 의존성으로 삼지 않는다.

## D04. 팀원 자리

GPT / Claude / Gemini / NotebookLM / Codex의 다섯 자리를 시각 기본안으로 둔다. 원래 데이터에 Gemini/NotebookLM이 통합된 팀원 하나뿐이면 좌석을 자동 복제·연결하지 않는다. 실제 member_id를 확인해 바인딩하거나 미연결 자리로 둔다. 역할 이름은 능력·제품 계정·실행 수의 증명이 아니다.

## D05. 진행률·이미지의 숫자

개념 이미지의 70%, 40%, 가상의 일정·날짜·날씨·알림 수는 구현 근거가 아니다. 기존 명세의 '확인된 완료 조건·검사 결과만 표시' 원칙을 유지한다. 실행이 없으면 없다고 표시한다.

## D06. 계약의 구분

새 `office-snapshot.schema.json`은 화면용 읽기 모델이다. 기존 `office-event.schema.json` Runner 수신 계약을 대체하거나 변경하지 않는다. 새 상태 이름(`external_work` 등)은 시각화용 enum이며 업무 DB 상태로 저장하지 않는다.
